# 시계열 그래프 추가 작업 — 인수인계 안내서

> **목적:** 대시보드 리포트에서 **세부항목(점수 박스)은 있지만 시계열 그래프가 없는 변수**에 시계열을 채운다.
> 직전에 "몸통 측굴 속도"를 이 방식으로 추가 완료했고, 같은 패턴을 다른 빈 항목에 반복하면 된다.

### 단일 소스 원칙(중요)

## 2. 시계열 추가 패턴 (직전 "측굴" 사례 그대로 따라하기)

세부 패널은 `report.engine.js` 안에 단계별로 있다: `_edBody<Stage>()` 함수가 HTML을 만들고,
`_redraw<Stage>Charts()` 가 `plotWin(...)` 으로 시계열을 그린다.

**3곳을 수정하면 시계열 1개가 추가된다:**

### (A) HTML에 canvas 추가 — 해당 `_edBody...` 함수 안, 카드 HTML에
```js
html+='<div class="card" style="grid-column:1 / -1">'
  +'<div style="font-size:13px;font-weight:800">제목</div>'
  +'<div class="note" style="margin-top:4px"><b>쉬운 설명:</b> 선수 눈높이 설명…</div>'
  +'<canvas id="ed-XX-새이름" style="width:100%;height:220px;display:block;margin-top:8px"></canvas>'
  +'<div class="note" style="font-size:11px;margin-top:3px">범례·해석</div>'
  +'</div>';
```

### (B) plotWin 호출 추가 — 해당 `_redraw...Charts()` 함수 안
```js
try{ plotWin('ed-XX-새이름', Object.assign({left:{label:'단위 (°/s 등)', lines:[
  {compute:function(t){var a=t.series.시리즈명; return a?a.map(function(x){return Math.abs(x);}):null;}, color:'#e8954e', label:'선이름', width:2.4}
  // 비교선 더 추가 가능
]}, extraEvents:ev([['이벤트라벨','#색']])}, W)); }catch(e){}
```
- `t.series.<시리즈명>` 이 실제 데이터(예: `Thorax_Ang_Vel_Y`). 사용 가능한 시리즈는 phases.js 변인 정의의 `S.<이름>` 참고.
- `W` 는 같은 함수 안에서 만들어진 시간창(startEv/endEv). 기존 차트 코드 복사해 쓰면 된다.
- FC/MER/BR 마커는 보통 자동(`noBuiltinEv` 안 주면).

### (C) (선택) 정면/측면 스틱 추가 — 측굴처럼 자세 강조가 필요할 때
- `report.engine.js` 의 `_trLatStick(cvId)` (정면·척추강조), `_trFcStick(cvId,view)` (측면/탑뷰) 가 복사용 템플릿.
- 정면 투영 = `[j[0], j[1]]`, 측면 = `[j[2], j[1]]`, 탑뷰 = `[j[0], j[2]]`.
- 프레임 연동 readout(각도·각속도 숫자)은 `_redrawTrFcSticks()` 안에서 현재 프레임 값으로 갱신하는 패턴 참고.

### 측굴 사례 실제 위치(검색어)
- HTML: `report.engine.js` 에서 `A-3. 몸통 측굴` 검색
- 차트: `_redrawTrCharts()` 안의 `ed-tr-lat`
- 스틱: 함수 `_trLatStick`

## 3. 시계열 없는 항목 인벤토리 방법

대부분의 운동학 변수(각도·각속도·힘·파워·에너지)는 이미 79개 차트로 커버됨.
**남은 빈 항목은 대개 "집계형 스칼라 지표"**(비율·타이밍 차이)라서 시계열이 자연스럽지 않을 수 있음 — 항목마다 "시계열이 의미 있나?" 판단 필요.

### 자동 인벤토리 절차(새 대화에서 실행)
1. `mech6.js MAP` 의 단계별 변인 키 목록을 뽑는다.
2. 각 변인의 바탕 시리즈(phases.js의 `S.<...>`)를 확인한다.
3. `report.engine.js` 에서 `t.series.<그 시리즈>` 가 `plotWin` 안에 등장하는지 grep → 없으면 "시계열 없음 후보".
4. 후보 중 **시간에 따라 변하는 곡선이 코칭에 의미 있는 것만** 채운다(순수 비율/단일 시점 값은 제외 가능).

### 우선 살펴볼 후보(예상 — 새 대화에서 확정할 것)
- **시계열이 의미 있어 채울 만한 것:** 단계별로 점수박스는 있으나 곡선이 빠진 운동학 항목(예: 일부 파워·에너지 생성률, 관절 모멘트 곡선 등).
- **시계열이 부적절(스칼라/타이밍) → 보통 제외:** `strideLen`(보폭), `grfDelay`(간격), `blockConvEff`·`rotKEgain`·`linRotRatio`(전환·전달 비율), `kneeContribPct`·`kneeTrunkLag`·`ppKneeTrunk`, `armTransferRatio`·`ppTrunkHum`·`ppShoElb`·`chainTiming`·`seqPct`·`whipRatio`.
  → 이런 항목은 시계열 대신 "분포 밴드·게이지"가 더 적절. 굳이 곡선이 필요하면 관련 원천 시리즈(예: 두 분절 파워 overlay)로 대체 표현.

## 5. 현재까지의 단계 모델(맥락)

6단계 = **동작 단계(motion phase)** 기준: 와인드업·스트라이드·블로킹·앞무릎·몸통·팔.
- 와인드업(3): hipHinge·freeMo·pelClose
- 스트라이드(12): 드라이브 + 착지자세·분리상태(leanBack·openAng·xfPeak·xfReleasedPctByFC)
- 블로킹(8): 제동·전환
- 앞무릎(8): 버팀·신전·골반회전
- 몸통(8): xfUnwindV·회전·굴곡·측굴·ME
- 팔(13): 견갑·MER·가속·릴리스·감속·시퀀스

3축 레이더(저장/생성/효율)는 **동작 단계와 별개로 항목 역할별 매핑 유지**(건드리지 않음).
```
